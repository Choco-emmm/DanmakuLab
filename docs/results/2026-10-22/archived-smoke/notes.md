## 场景与结果

10 个同房间观众，包含 1 个发送者；额外 1 个独立房间探针，合计 11 条连接。单 k6 VU 协调全部连接，等待加入确认后启动发送。1 条/秒，共 60 条，发送后排空 1.5 秒。

| 指标 | 结果 |
| --- | --- |
| 加入确认 | 11 |
| 输入 / 接受 | 60 / 60 |
| 理论投递 / 客户端唯一接收 | 600 / 600 |
| 每观众完整性检查 | 10 / 10 通过，各收到 60 条 |
| 重复 / 串房 / 顺序违反 / 错误 | 均为 0 |
| 脚本完整迭代 | 1，正常退出，k6 退出码 0 |
| 服务端预期投递 / 提交发送 | 600 / 600 |
| 结束后服务端连接 / 房间 | 0 / 0 |

客户端同机时间戳样本 600 个，毫秒分辨率；P50 为 1ms、P95 为 2ms、最大 4ms。0ms 样本保留。本轮默认摘要没有 P99，不能从 P95 或最大值推算 P99。后续容量脚本需显式输出 P99，并增加实际负载速率、GC、网络与时序资源采集。

消息使用固定短正文 `smoke message`，完整输入 JSON 的 ID 与时间戳动态生成；本轮没有把消息填充到 256 字节，不是候选容量验收场景。服务前后指标仅为快照，不是峰值或稳态内存证据；`jvm.memory.used` 未按 area 过滤，包含 heap 与 nonheap。

## 浏览器与功能验证

最终打包版本使用本机已有 Chromium 进行真实双页面操作：双向广播、HTML 输入以文本显示、换房隔离、主动断开后重进、模拟连接关闭后的自动重连和重新加入、375px 下无横向溢出、无未捕获 JavaScript 错误，均通过。

浏览器截图保存在本机被忽略的 `load-results/demo-desktop.png` 和 `load-results/demo-mobile.png`；12 项自动化测试可使用 Maven 重现。浏览器 smoke 是临时 QA 脚本，尚未作为跨机器 UI 测试套件交付。gstack browse 因缓存 Chromium 版本不匹配无法启动，改用已有 Playwright 与 Chromium 完成上述验证。

## 限制与下一步

本轮证明协议、计数和连接清理可运行，不证明 1,000 连接容量、慢消费者保护或热点隔离。没有基线/优化性能对照。下一步实现 T1 阶梯负载及持续指标采集，确认压测器有效后再注入真实慢连接。
